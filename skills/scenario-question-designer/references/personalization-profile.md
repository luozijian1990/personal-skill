# 个性化画像规则

## 可选输入

| 字段 | 对场景设计的影响 |
|---|---|
| 目标岗位 | 选择领域、职责和表达方式 |
| 目标级别 | 调整系统范围、风险和决策责任 |
| 目标 JD | 提取必备技术、业务场景和加分项 |
| 真实经历 | 设计验证已声明能力的场景，不复制敏感事实 |
| 强项 | 增加机制、边界和取舍 |
| 弱项 | 提供更多入口信息，检验知识结构和调查顺序 |
| 使用目的 | 区分自测、模拟面试、复习和题目策划 |

## 使用原则

1. 优先复用用户已经提供的信息，只追问会改变场景核心的问题。
2. 缺少画像时进入通用模式，不猜测岗位、年限或项目经历。
3. 工作年限只作参考。场景难度由歧义、范围、风险、约束和责任决定。
4. Roadmap 知识或模拟条件不能证明用户做过某个项目。
5. 用户弱项用于决定训练优先级，不应被写成已经掌握。
6. 用户强项或简历声明适合用更深的机制、边界和恢复验证来检验。

## 去标识化

输出只能保留必要的抽象画像，例如“目标为高级平台工程师”“有 Kubernetes 运维经验”。删除或泛化：

- 姓名、用户名、联系方式；
- 本地绝对路径和私有仓库地址；
- 公司、客户、业务线和内部系统名称；
- 主机名、IP、账号、令牌、许可证和机器标识；
- 未经允许的真实规模、时间、损失和事故细节。

本地来源只记录仓库相对路径和标题路径。真实事故可以改写为“某生产集群”“某核心服务”等去标识化表述。
