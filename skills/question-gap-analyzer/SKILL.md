# 个性化面试题缺口分析

把 Roadmap 或 Markdown 知识材料转成一份可审核的面试题候选集。先分析、再确认、后生成；不要把每个标题机械转换成题目。

## 必读资料

开始前完整读取：

- `references/personalization-profile.md`：个人画像的收集、缺省和隐私规则。
- `references/candidate-review-template.md`：候选审核报告格式。
- `references/coverage-rubric.md`：双模式、覆盖判断和候选决策标准。

只有用户确认候选、准备生成完整题目时，再读取 `references/question-template.md`。

## 边界

- 只读取用户指定的知识源、画像/JD 和可选题目集合；不擅自扫描主目录或其他仓库。
- 不修改知识源和已有题目。
- 没有已有题目集合时使用“策划模式”，不得写“未覆盖”“已经覆盖”或伪造检索证据。
- 个人画像只用于调整相关性、难度和考察角度，不能把知识材料包装成用户亲自做过的项目。
- 用户确认候选前不生成完整题目；确认普通题不等于确认场景题。
- 不操作题库、数据库、CLI 或外部系统，只输出通用 Markdown。
- 不在输出中保留个人姓名、用户名、本地绝对路径、私有仓库地址、内部主机/IP、账号和凭据。

## 固定输出路径

以调用时的工作目录为基准：

```text
./question-gap-analyzer-output/
├── candidate-review.md
├── question-set.md
└── questions/
    └── <stable-id>.md
```

- 分析阶段只写 `candidate-review.md`。
- 用户确认后，每道普通题写入独立文件，并重建 `question-set.md` 索引。
- `SCENARIO_CANDIDATE` 只保留在审核报告中，交给场景题设计流程处理，不在这里生成场景题。
- 目标文件存在时先说明覆盖范围；未经确认，不静默覆盖。

## 输出层级

- 默认使用精简审核稿：先列汇总表，再详细展开 `NEW_QUESTION`、`SCENARIO_CANDIDATE` 和 `NEEDS_REVIEW`。
- `ALREADY_COVERED` 与 `DO_NOT_CREATE` 默认只保留 ID、来源、结论和一句证据；用户要求复核时再展开完整覆盖分析。
- 用户要求“详细报告”时，才为全部候选展开 `candidate-review-template.md` 中的完整字段。
- 数量是上限，不是配额。材料不足时减少候选，并说明还缺少哪些知识范围；不得拆分近义题凑数。

## 异常与兜底

| 触发条件 | 一线处理 | 仍失败时的兜底 |
|---|---|---|
| 知识源不存在、不可读或没有 Markdown 正文 | 报告准确路径和读取结果，请用户修正输入 | 停止分析，不用常识替代指定材料 |
| 用户描述的主题与实际材料不一致 | 列出“用户预期主题”和“实际读取主题” | **停在确认点**，未经确认不得切换分析对象 |
| 已有题目路径为空、不可读或只有索引没有正文 | 降级为策划模式，并说明无法判断覆盖 | 若用户必须做缺口分析，停止并要求提供可读题目正文 |
| 画像、JD 与知识源互相冲突 | 标记冲突并使用 `NEEDS_REVIEW` | 不替用户决定哪个输入更可信 |
| 输入过大，无法在一轮完整读取 | 按用户指定范围分批，记录已分析和未分析部分 | 没有分批范围时先给目录级计划，不声称完成全量覆盖 |
| 输出文件已存在 | 展示将新增、重建和保持不变的文件 | 未获覆盖确认时只在对话中展示草稿，不写文件 |
| 用户确认的 ID 不存在或结论不允许当前操作 | 列出有效 ID 和当前结论 | 跳过无效 ID，不猜测映射关系 |

## 工作流程

### 1. 确认输入与模式

至少需要一个明确的 Markdown 文件或目录。先检查目标仓库的 `AGENTS.md` 等约束，只纳入用户指定的正式内容；默认排除生成 HTML、缓存、构建产物、依赖目录和既有输出目录。

根据输入选择模式：

- **策划模式**：没有已有题目集合。评估知识单元的面试价值和个人相关性。
- **缺口模式**：有明确的已有题目文件或目录。额外判断覆盖程度、证据置信度和重复风险。

在报告开头明确模式。若用户口头说“分析缺口”但没有提供题目集合，说明限制并继续采用策划模式，不要阻塞整个任务。

### 2. 建立个性化画像

按 `personalization-profile.md` 读取用户已提供的目标岗位、级别、JD、真实经历、强弱项和用途。只追问会实质改变筛选结果的缺失信息。

用户未提供画像时允许使用“通用模式”：依据知识源本身筛选有区分度的题目，并把个性化依据标记为“未提供”。不要猜测年限、岗位或项目经验。

### 3. 提取知识单元

按语义章节提取，不只看文件名或标题。保留：

- 来源相对路径和标题路径；
- 核心概念、机制、操作与约束；
- 示例、图表、代码和上下文能够支持的事实；
- 中英文别名、缩写和相邻机制。

合并只是在不同文件重复表述的同一知识单元；能够考察不同能力的机制、排障、治理和权衡保持独立。

### 4. 分析覆盖（仅缺口模式）

按照 `coverage-rubric.md`：

1. 用标题、别名、机制、异常、操作和约束召回相关题目。
2. 读取候选题完整正文，而不是只比较标题。
3. 分别判断概念、机制、实操、排障、场景和治理维度。
4. 记录相关题目的相对路径或稳定标识以及判断证据。

检索无精确词命中只是弱证据。证据不足时使用 `NEEDS_REVIEW`。

### 5. 判断个人相关性与面试价值

同时考虑：

- 与目标岗位/JD 的关联；
- 与用户真实经历、强项和弱项的关系；
- 是否能区分背诵、理解、实操和负责生产结果；
- 是否适合普通题、追问或独立场景题；
- 是否只是版本罗列、参数百科或低价值记忆点。

弱项可以提高学习优先级，但不能自动提高用户声称的能力等级。用户简历或经历中明确声称熟悉的主题，可设计更深入的机制或边界追问。

### 6. 形成候选决策

为每个候选选择一个结论：

- `NEW_QUESTION`：适合生成普通题。
- `SCENARIO_CANDIDATE`：主要价值来自生产情境、证据和方案权衡。
- `ALREADY_COVERED`：仅缺口模式使用；已有题已直接考察同一能力。
- `DO_NOT_CREATE`：价值低、偏离目标或重复风险过高。
- `NEEDS_REVIEW`：来源事实、覆盖证据或个人相关性不足。

候选数量服从质量，不为达到配额制造近义题。普通题和场景题不得只通过替换产品名或数值重复考察同一能力。

### 7. 输出候选审核报告

按 `candidate-review-template.md` 写入 `candidate-review.md`。每个候选使用本轮稳定 ID，例如 `QGA-001`，并记录来源、个性化依据、模式适用字段、候选结论、拟定标题和用户确认项。

停在审核门，等待用户明确确认：

- 哪些 ID 生成普通题；
- 最终难度和考察重点；
- 哪些 `SCENARIO_CANDIDATE` 交给场景题设计；
- 哪些候选跳过或修改。

“都可以”只有在候选列表、数量和默认难度已经完整展示时才能视为整批确认；否则要求明确范围。

## 🔴 CHECKPOINT · 候选确认

展示候选审核报告后立即停止，不生成完整题目或更新题目索引。

🛑 **STOP**：只有用户明确确认候选 ID、题型和难度后，才能进入步骤 8。普通题确认不能推导为场景题确认。

### 8. 生成已确认的普通题

用户确认后：

1. 读取 `question-template.md`。
2. 只生成明确确认且结论为 `NEW_QUESTION` 的候选。
3. 保持确认的考察目标和难度，不擅自改变为场景题。
4. 每题写入 `questions/<stable-id>.md`。
5. 生成 `question-set.md`，列出 ID、标题、来源、适合对象、难度和文件链接。
6. 对输出做敏感信息检查，并确认没有把用户未声明的经历写成事实。

生成后报告实际文件、跳过项和仍待确认的场景候选。

## 场景题交接契约

每个已确认的 `SCENARIO_CANDIDATE` 至少携带以下字段，使下游流程无需读取本 Skill 也能理解候选：

```yaml
candidate_id: QGA-004
source: relative/path.md > heading
knowledge_unit: 核心知识单元
assessment_goal: 核心考察目标
target_role: 目标岗位或通用
difficulty: 初级 | 中级 | 高级
personalization_boundary: 不得推断的个人经历
confirmed_constraints: 用户确认保留的条件
unresolved_facts: 仍待核实的信息
```

## 反例黑名单

- 不要把每个 Markdown 标题机械转换成一道题。
- 不要为满足数量拆出只换措辞、产品名或数值的近义题。
- 不要把关键词未命中直接判定为“未覆盖”。
- 不要只比较题目标题而跳过相关题目正文。
- 不要把 Roadmap 内容写成用户亲自完成的项目或事故经历。
- 不要把弱项、学习目标或岗位要求写成用户已经具备的高级能力。
