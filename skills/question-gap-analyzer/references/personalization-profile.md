# 个性化画像规则

## 最小输入

知识源路径是唯一必需输入。以下信息均可选：

| 字段 | 用途 |
|---|---|
| 目标岗位 | 调整知识相关性和题目表达 |
| 目标级别 | 调整系统范围、责任边界和追问深度 |
| 目标 JD | 提取必备项、加分项和业务场景 |
| 真实经历 | 设计能验证已声明能力的题目 |
| 强项 | 增加机制、边界和权衡类追问 |
| 弱项 | 提高补强优先级，不伪装成已有经验 |
| 本次用途 | 区分求职准备、自测、模拟面试和题目策划 |
| 数量/配额 | 控制输出规模和领域分布 |

## 收集原则

1. 优先复用用户已经提供的信息，不重复询问。
2. 只追问会改变筛选结果的内容；缺少可选字段时允许进入通用模式。
3. 只给公司名或岗位名不等于完整 JD。不得补写未提供的职责和要求。
4. 工作年限只是参考，不直接决定难度。难度还取决于系统范围、信息歧义、业务约束、风险和责任边界。
5. 个人经历必须来自用户明确陈述或用户指定材料。Roadmap 内容不能反向证明用户做过相关项目。

## 个性化使用方式

- 与目标岗位高度相关且属于用户弱项：提高学习与自测优先级。
- 与用户强项或简历声明直接相关：提高机制、故障、边界和权衡深度。
- 与目标岗位无关：通常降低优先级，即使 Roadmap 内容很完整。
- 缺少个人画像：使用通用技术面试价值，不猜测用户背景。
- 画像与来源冲突：在审核报告中明确冲突，使用 `NEEDS_REVIEW`，不替用户决定哪个是真的。

## 隐私与输出

审核报告和最终题目只保留完成个性化所需的去标识化摘要，例如“5 年平台运维经验”“目标为高级 SRE”。不得输出：

- 姓名、用户名、联系方式；
- 用户主目录和本地绝对路径；
- 私有仓库地址、内部域名、主机名或 IP；
- 客户名称、账号标识、令牌、许可证和其他凭据；
- 未经用户允许的真实公司或事故细节。

本地来源统一记录为仓库相对路径和标题路径。
