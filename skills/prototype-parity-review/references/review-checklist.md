# 原型一致性审查清单

按项目实际范围使用。没有对应能力时标记 `NOT_APPLICABLE`，不要为了填满清单而发明要求。

## 视觉一致性

### 布局与层级

- 页面骨架、主要区域比例和阅读顺序是否一致？
- Navigation 的位置、分组、选中状态和层级是否一致？
- 核心信息是否仍处于原型定义的视觉焦点？
- 列表、卡片、表格、详情面板的信息密度是否被改变？

### 视觉语言

- 字体家族、字号、字重和行高是否保留？
- 颜色角色、对比度和强调色用法是否一致？
- 间距、边框、圆角、阴影和分隔方式是否保留？
- 图标、图表和状态标识是否表达相同含义？
- 是否出现组件库默认风格覆盖原型的情况？

### 状态与响应式行为

- Default、Hover、Focus、Selected、Disabled 状态是否可识别？
- Loading、Error、Empty、Success、Progress 是否存在且位置合理？
- Dialog、Drawer、Popover、Toast 是否保持原型的尺寸、层级和关闭行为？
- 目标 viewport 下是否存在溢出、遮挡、折行或布局坍塌？
- 原型明确的响应式重排是否得到保留？

## 交互一致性

- Navigation 与深链接是否到达对应页面？
- Tab、筛选、搜索、排序和分页是否改变正确的数据视图？
- Dialog、Drawer 和菜单的打开、取消、确认与关闭是否一致？
- 表单字段、默认值、校验、提交和错误反馈是否一致？
- 高风险操作是否保留确认、阻断和结果反馈？
- 长任务是否保留提交、进度、失败、重试/取消和完成状态？
- 权限差异是否保持相同的可见性与阻断结果？
- 刷新、返回和重复操作是否维持原型定义的状态行为？

## 范围完整性

- React 是否遗漏了原型已有页面、状态或 Flow？
- React 是否新增未经批准的入口、流程或业务规则？
- 差异是否有明确的人工批准记录？
- 是否把 Mock 行为误报为真实后端或生产行为？
